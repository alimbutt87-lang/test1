Behavioural Questions

Azure Engineer interviews assess your problem-solving approach, communication, teamwork, and experience managing Azure infrastructure.

  • Describe a time you automated an Azure infrastructure deployment using Azure DevOps. What challenges did you face?
    Tips: ['Mention specific Azure services (VMs, App Service, AKS, Key Vault)', 'Explain the automation tool: Azure DevOps Pipelines, ARM templates, Bicep, or Terraform', 'Describe the challenge and how you resolved it', 'Highlight the business impact (time saved, fewer errors)']
  • Tell us about a production incident in Azure. How did you troubleshoot and resolve it?
    Tips: ['Use a real or realistic Azure scenario (e.g., App Service outage, AKS pod crash, Network Security Group misconfiguration)', 'Walk through your troubleshooting process: Azure Monitor, Log Analytics, Application Insights, or diagnostic logs', 'Explain what you learned and how you prevented similar issues', 'Show understanding of Azure monitoring and alerting']
  • How do you stay current with Azure updates and new features?
    Tips: ['Mention Azure Learn, documentation, or official Microsoft training', 'Reference Azure roadmap or tech communities', 'Share an example of adopting a new Azure service (e.g., Azure Container Apps, Entra ID features)', 'Show genuine interest in continuous learning']
  • Describe a time you collaborated with developers to deploy and secure a containerised application on AKS.
    Tips: ['Explain AKS setup: nodes, pods, namespaces, RBAC', 'Mention security practices: network policies, Entra ID authentication, Azure Policy', 'Highlight cross-team communication', 'Show understanding of application requirements']
  • How have you optimised Azure costs in a previous project?
    Tips: ['Use Azure Cost Management + Billing insights', 'Mention specific optimisations: reserved instances, spot VMs, auto-scaling, Blob Storage tiering', 'Quantify savings if possible', 'Show proactive cost awareness']
  • Tell us about a time you improved security in an Azure environment.
    Tips: ['Reference Azure services: Key Vault, Managed Identities, Entra ID RBAC, Defender for Cloud, Azure Policy', 'Explain the security gap you identified', 'Describe the solution and its implementation', 'Highlight measurable improvements (e.g., reduced secrets exposure, improved compliance)']
  • How do you handle a situation where a team member disagrees with your Azure architectural decision?
    Tips: ['Show openness to discussion and data-driven decisions', 'Reference Azure best practices and trade-offs', 'Emphasise communication and documentation', 'Demonstrate confidence in your expertise while respecting others']

Azure Networking, Compute & Storage

Hands-on questions on Azure VNets, NSGs, load balancing, compute resources, and storage services.

  • Design a network architecture using Azure VNets and NSGs (Network Security Groups) that isolates front-end, middle-tier, and database tiers while allowing secure communication.
    Tips: ['Create separate VNets or subnets for each tier', 'Define NSG rules: inbound/outbound for each tier', 'Use service tags (e.g., AzureAppService) where appropriate', 'Mention Network Peering or VPN Gateway for connectivity', 'Explain least-privilege access principles']
    What interviewers look for: A strong answer sounds like: 'I'd use an Application Gateway with WAF for the public-facing tier and an internal load balancer for service-to-service traffic, with NSGs restricting east-west traffic between subnets.' A weak answer sounds like: 'I'd use Azure Load Balancer.'
    Sample Answer Guidance: I'd create a single VNet with three subnets: front-end, application, and database. The front-end subnet's NSG allows inbound HTTPS (443) from the internet; the application subnet's NSG allows inbound only from the front-end NSG and outbound to the database subnet; the database NSG allows inbound only from the application subnet on port 3306 or 1433. Azure service tags simplify rules, and I'd use User Defined Routes (UDRs) to force traffic through a Network Virtual Appliance if needed for deep packet inspection.
  • Explain the differences between Azure Load Balancer and Application Gateway. When would you use each with Azure VMs and App Service instances?
    Tips: ['Azure Load Balancer: Layer 4 (transport), stateless, lower latency', 'Application Gateway: Layer 7 (application), SSL termination, URL-based routing, WAF', 'Load Balancer: good for VMs, non-HTTP protocols, ultra-high throughput', 'Application Gateway: good for web applications, advanced routing, security', 'Mention Azure Front Door for global distribution']
    What interviewers look for: A strong answer sounds like: 'Load Balancer is stateless at Layer 4 and works for any protocol; Application Gateway understands HTTP headers and can route by URL path or hostname, plus it has built-in WAF.' A weak answer sounds like: 'Load Balancer and Application Gateway both do load balancing.'
    Sample Answer Guidance: Azure Load Balancer operates at Layer 4 with no awareness of HTTP; it's stateless, ultra-low latency, and ideal for non-HTTP protocols or extreme throughput scenarios with Azure VMs or VM Scale Sets. Application Gateway is Layer 7, terminates SSL/TLS, understands URL paths and hostnames for routing, and includes a Web Application Firewall (WAF) for security—perfect for web applications, microservices, and App Service instances. For global routing with failover, I'd layer Azure Front Door on top of either.
  • How would you configure Azure VNets, subnets, and NSGs to ensure a web server can receive HTTPS traffic but a backend database cannot be accessed directly from the internet?
    Tips: ['Web tier in public subnet with NSG allowing inbound HTTPS (443)', 'Database tier in private subnet with NSG allowing inbound only from web tier', 'Use private endpoints for Azure SQL Database or Blob Storage', 'Mention User Defined Routes (UDRs) for advanced routing', 'Explain the principle of least privilege']
    Sample Answer Guidance: I'd place the web server in a public subnet with an NSG permitting inbound HTTPS (443) from the internet and outbound to the database subnet. The database tier goes in a private subnet with an NSG allowing inbound only from the web server's NIC or the web tier's subnet (using source IP address or Application Security Group). For Azure SQL Database, I'd use a Private Endpoint within the VNet and disable public internet access entirely, ensuring zero direct internet exposure.
  • Describe your approach to scaling Azure App Service and Azure Functions for variable demand. What auto-scaling options would you configure?
    Tips: ['App Service: Auto Scale Plans based on CPU, memory, or custom metrics', 'Azure Functions: Consumption plan auto-scales automatically; Premium plan for guaranteed resources', 'Use Azure Monitor to define scaling rules and thresholds', 'Monitor scaling effectiveness with Application Insights', 'Consider cost implications of scaling strategy']
  • You need to store 10TB of unstructured data on Azure. Should you use Blob Storage, Azure Files, or Managed Disks? Justify your answer and explain tier selection (Hot, Cool, Archive).
    Tips: ['Blob Storage: for unstructured data, static content, backups (Hot/Cool/Archive tiers)', 'Azure Files: for SMB/NFS file shares, on-premises integration', 'Managed Disks: for VM storage only', 'Explain access patterns and cost trade-offs', 'Consider lifecycle management and replication']
  • How would you implement disaster recovery for an Azure App Service application? What are the RPO and RTO implications of your approach?
    Tips: ['Geo-replication or multi-region deployment using Azure Traffic Manager', 'Database replication: Azure SQL active-geo replication or Cosmos DB global distribution', 'Blob Storage geo-redundant storage (GRS) or read-access GRS (RA-GRS)', 'Define RTO (Recovery Time Objective) and RPO (Recovery Point Objective)', 'Test failover procedures regularly']
    Sample Answer Guidance: I'd deploy App Service instances in two regions with Azure Traffic Manager routing based on health probes for active-active failover. For the database, I'd use Azure SQL Database's active-geo replication for near-synchronous failover (RPO ~5 seconds), with Blob Storage using read-access geo-redundant (RA-GRS) replication and Azure Monitor-triggered Logic Apps automating failover when the primary region fails.
  • Explain how you would set up a hybrid network connecting on-premises infrastructure to Azure using Azure VPN Gateway or ExpressRoute. What are the trade-offs?
    Tips: ['Azure VPN Gateway: site-to-site or point-to-site, lower cost, internet-based', 'ExpressRoute: dedicated connection, higher reliability, consistent bandwidth, higher cost', 'Design VNet address space to avoid overlaps with on-premises', 'Explain failover and redundancy strategies', 'Consider bandwidth and latency requirements']
    Sample Answer Guidance: Azure VPN Gateway uses IPsec over the internet for lower cost with variable latency; ExpressRoute provides dedicated circuits with consistent bandwidth and lower latency, ideal for mission-critical workloads. For resilience, run both in parallel or deploy dual ExpressRoute circuits, and configure forced tunnelling via NSGs to ensure all on-premises traffic routes through the hybrid connection.
  • Design an Azure infrastructure using Azure Front Door that serves content globally with caching, WAF protection, and failover across regions.
    Tips: ['Azure Front Door: Layer 7 load balancing, geo-routing, anycast routing', 'Integrate WAF rules for security', 'Configure backend pools across multiple regions', 'Set health probes for failover detection', 'Explain caching strategy and cache-control headers']

Azure Identity, Security & Monitoring

Deep-dive on Azure Entra ID, RBAC, secrets management, and comprehensive monitoring with Azure Monitor and Log Analytics.

  • Design an Azure Entra ID (Azure AD) identity and access management strategy for a multi-team organisation. How would you implement RBAC and Managed Identities?
    Tips: ['Create Azure Entra ID tenant structure and groups (security groups, M365 groups)', 'Implement role-based access control (RBAC) with custom roles where needed', 'Use Managed Identities for applications and VMs to avoid storing credentials', 'Explain service principals vs managed identities', 'Mention Conditional Access policies for security']
    What interviewers look for: A strong answer sounds like: 'I'd use system-assigned Managed Identities for VMs and application code, enforce MFA with Conditional Access policies, and create custom roles scoped to resource groups for least privilege.' A weak answer sounds like: 'I'd use Azure Entra ID and RBAC.'
    Sample Answer Guidance: I'd create security groups in Azure Entra ID per team and assign custom roles scoped to resource groups for least privilege, using system-assigned Managed Identities for AKS pods and App Service instances to authenticate without storing credentials. Layer Conditional Access policies requiring MFA for risky sign-ins, with all access logged to Log Analytics for auditing.
  • How would you securely store and rotate secrets (API keys, connection strings) in Azure Key Vault? Explain the access control and rotation mechanisms.
    Tips: ['Use Azure Key Vault for secrets, keys, and certificates', 'Implement access policies or Azure RBAC for key vault access', 'Enable soft delete and purge protection', "Configure auto-rotation using Key Vault's native rotation or Azure Automation", 'Audit access with Azure Monitor and Log Analytics']
    Sample Answer Guidance: I'd store secrets in Azure Key Vault with RBAC and use Key Vault's native auto-rotation feature with Azure Functions to refresh secrets periodically. Enable soft-delete, purge-protection, and integrate diagnostics with Log Analytics to audit all access attempts and create alerts for suspicious activity.
  • Explain how you would implement Azure Policy to enforce compliance across your Azure subscriptions. Give examples of policies you would use.
    Tips: ['Use Azure Policy to enforce standards (naming conventions, allowed resource types, encryption)', 'Explain policy vs initiative', 'Example: require NSGs on all VNets, enforce encryption on Blob Storage, mandate tags on resources', 'Use policy effects: Deny, Audit, Append, Modify, Disabled', 'Monitor policy compliance in Azure portal']
  • Design a monitoring and alerting strategy using Azure Monitor, Log Analytics, and Application Insights for a production application. What metrics and logs would you track?
    Tips: ['Azure Monitor: collect metrics and logs from all Azure resources', 'Log Analytics: central repository for logs with KQL (Kusto Query Language) for analysis', 'Application Insights: APM for applications, dependency tracking, performance monitoring', 'Define key metrics: CPU, memory, latency, error rates, availability', 'Set up alerts for critical thresholds and use action groups for notifications']
    Sample Answer Guidance: I'd centralise metrics and logs in Log Analytics using Azure Monitor with Application Insights tracking dependencies and request latency. Define KQL queries for API response time (p95, p99), error rates, and availability, creating metric alerts with dynamic thresholds that route critical incidents via action groups to PagerDuty or Slack.
  • How would you detect and respond to security threats in Azure using Defender for Cloud and Azure Sentinel? Explain the workflow.
    Tips: ['Defender for Cloud: continuous assessment, threat detection, recommendations', 'Review Defender alerts for VMs, databases, storage, containers', 'Use Azure Sentinel for SIEM and SOAR capabilities', 'Explain incident response workflow: detection, investigation, containment, eradication', 'Set up automated responses using Logic Apps or playbooks']
    Sample Answer Guidance: Defender for Cloud continuously scans Azure resources and generates alerts; critical alerts flow into Azure Sentinel, which correlates events using rules and ML models to create incidents. I'd create playbooks automating response: isolate compromised VMs by modifying NSGs, trigger ticketing, and notify teams, with Log Analytics storing all events for post-incident KQL analysis.
  • Describe how you would implement role-based access control (RBAC) for an Azure subscription. What are built-in roles, and when would you create custom roles?
    Tips: ['RBAC: role assignment to principal (user, group, service principal) at scope (subscription, resource group, resource)', 'Built-in roles: Owner, Contributor, Reader, specific service roles', "Custom roles: when built-in roles don't fit the principle of least privilege", 'Example custom role: allow deploying App Service and functions but no VM management', 'Regularly audit role assignments']
  • How would you configure encryption for data at rest and in transit across Azure services (Blob Storage, Azure SQL, App Service)? Explain encryption mechanisms.
    Tips: ['At rest: transparent data encryption (TDE) for SQL, encryption at rest for Blob Storage', 'Customer-managed keys using Key Vault', 'In transit: TLS/SSL for all communications, enforce HTTPS on App Service', 'Application-level encryption for sensitive data', 'Audit encryption settings with Defender for Cloud']

Azure IaC, Automation & AKS

Infrastructure as Code with ARM templates and Bicep, Azure DevOps automation, AKS cluster management, and cost optimisation.

  • Compare ARM templates, Bicep, and Terraform for defining Azure infrastructure. When would you use each approach?
    Tips: ['ARM templates: JSON-based, native Azure, verbose, good for simple deployments', 'Bicep: simplified syntax over ARM templates, easier to read, same Azure integration', 'Terraform: multi-cloud, HCL syntax, state management, good for hybrid environments', 'Discuss modularity, reusability, and team preference', 'Mention state management and version control best practices']
    Sample Answer Guidance: Bicep is Azure-native with cleaner syntax than ARM templates, ideal for Azure-only deployments with modular components. Terraform excels in multi-cloud environments with stronger state management. Store state in Azure Storage with versioning, commit IaC to Git, and automate deployments via Azure DevOps Pipelines with separate environment stages.
  • Design an Azure DevOps pipeline to build, test, and deploy a containerised application to AKS with automated rollbacks on failure.
    Tips: ['Build stage: compile code, run unit tests, build Docker image', 'Push: upload image to Azure Container Registry (ACR)', 'Deploy to AKS: use Helm or Kustomize, blue-green or canary deployments', 'Test: smoke tests in staging environment', 'Rollback: automate rollback if health checks fail', 'Use Azure DevOps Pipelines for orchestration']
    Sample Answer Guidance: Build Docker images and push to Azure Container Registry (ACR) with semantic versioning, then deploy via Helm charts stored in ACR using canary deployment (traffic split via Application Gateway) for staging smoke tests. Configure Kubernetes liveness/readiness probes; if health fails, Helm automatically rolls back the previous stable release with alerts to Log Analytics.
  • How would you set up and manage an Azure Kubernetes Service (AKS) cluster? Explain node pools, scaling, networking, and security.
    Tips: ['Create AKS cluster with managed control plane', 'Configure node pools: different VM sizes for workloads (system pool, user pool)', 'Enable auto-scaling for horizontal and vertical scaling', 'Network: integrate with Azure VNets, use CNI for network policies', 'Security: Entra ID integration, RBAC, Pod Security Policies, Defender for Cloud', 'Monitoring: Container Insights for cluster visibility']
    Sample Answer Guidance: Create an AKS cluster with managed control plane in an Azure VNet using CNI for network policies, with separate system and user node pools supporting HPA/VPA scaling. Enable Azure Entra ID RBAC, enforce Pod Security Standards via Azure Policy, integrate Azure Defender for container scanning, and use Managed Identity to pull images from ACR.
  • Design a deployment strategy for AKS using Helm charts and Azure DevOps. How would you handle environment-specific configurations (dev, staging, prod)?
    Tips: ['Create Helm charts for templating Kubernetes manifests', 'Use values.yaml for environment-specific configuration', 'Azure DevOps Pipelines: separate stages for each environment', 'Implement approval gates for prod deployments', 'Version Helm charts and store in Azure Container Registry', 'Use secrets from Key Vault for sensitive config']
    Sample Answer Guidance: Create Helm charts with environment-specific values files for dev, staging, and production in Azure DevOps Pipelines. Inject secrets from Azure Key Vault using the Azure Keyvault Kubernetes provider to avoid storing credentials in Git.
  • Explain how to implement Infrastructure as Code (IaC) for managing Azure resources at scale. How would you handle drift and maintain consistency?
    Tips: ['Define IaC strategy using Bicep or Terraform', 'Store definitions in Git with version control', 'Use Azure DevOps Pipelines for automated deployments', 'Detect drift: compare declared state vs actual state', 'Implement guardrails with Azure Policy', 'Automate remediation of drift using Azure Automation or DevOps']
    Sample Answer Guidance: Define infrastructure with Bicep or Terraform in Git with branch protection, automating deployments via Azure DevOps Pipelines using 'terraform plan' before apply. Detect drift by comparing declared state versus Azure Resource Graph queries; Azure Policy enforces standards and blocks non-compliant changes. Trigger Azure Automation runbooks for drift remediation using Managed Identities, logging all changes to Log Analytics.
  • How would you optimise Azure costs using Azure Cost Management + Billing? What strategies would you implement?
    Tips: ['Analyse costs by service, subscription, and resource using Azure Cost Analysis', 'Implement Azure Hybrid Benefit for on-premises software', 'Use Reserved Instances (RIs) for predictable workloads', 'Use Spot VMs for non-critical workloads', 'Right-size resources: shutdown unused resources, downsize over-provisioned resources', 'Implement chargeback models using tags and subscriptions']
    Sample Answer Guidance: Use Azure Cost Management + Billing to analyse costs by resource group and tag; purchase Reserved Instances for baseline production workloads and Spot VMs for non-critical batch jobs (80% discount). Implement Blob Storage lifecycle policies for Cool/Archive tiers, Azure Automation runbooks to shutdown non-production resources outside business hours, and chargeback tags to allocate costs to business units.
  • Design an automation solution using Azure Automation to manage Azure resources (start/stop VMs, run maintenance scripts). How would you schedule and monitor execution?
    Tips: ['Create runbooks (PowerShell or Python) for automation tasks', 'Use Automation Accounts with Managed Identity for secure authentication', 'Schedule runbooks using schedules or webhooks', 'Monitor execution with Azure Automation job logs', 'Handle errors and notifications using Automation features', 'Integrate with Log Analytics for auditing']

Common Mistakes

Confusing Azure services with cloud-agnostic concepts

Azure Engineer interviews expect hands-on knowledge of specific Azure services. Vague answers about 'cloud infrastructure' without mentioning Azure VNets, NSGs, App Service, AKS, Entra ID, Key Vault, or Azure DevOps will not impress. Always reference the specific Azure service you would use and explain how it works.

Not understanding the difference between similar Azure services

Candidates often conflate Azure Load Balancer with Application Gateway, or Azure App Service with Azure Functions. Load Balancer operates at Layer 4 and is stateless; Application Gateway operates at Layer 7 with advanced routing. App Service is for long-running applications; Functions are serverless and event-driven. Understand these distinctions clearly.

Overlooking security from the start

Security is not an afterthought in Azure interviews. Candidates who design architectures without mentioning Entra ID, RBAC, Key Vault, Managed Identities, NSGs, or Azure Policy will lose points. Always think about identity, secrets management, network isolation, and encryption (at rest and in transit).

Ignoring cost and scalability considerations

Azure Engineers must balance performance with cost. Failing to discuss auto-scaling strategies, resource sizing, Reserved Instances, Spot VMs, or storage tiering shows incomplete thinking. Mention Azure Cost Management + Billing and demonstrate cost awareness in your architectural decisions.

Lack of hands-on experience with Azure DevOps and IaC

Modern Azure Engineers must be comfortable with Azure DevOps Pipelines, Bicep, and basic Terraform. If you cannot explain how to deploy infrastructure as code or set up a CI/CD pipeline, you're at a disadvantage. Practise building and deploying real applications with these tools.

Evaluation Criteria

Azure Service Depth: Demonstrate hands-on familiarity with Azure VNets, NSGs, Load Balancer, Application Gateway, App Service, Azure Functions, AKS, Entra ID, Key Vault, Azure Monitor, and Azure DevOps. Mention specific configuration options and trade-offs.

Problem-Solving Approach: Show methodical thinking when designing architectures or troubleshooting issues. Ask clarifying questions, consider multiple solutions, and justify your recommendations with Azure best practices.

Security Mindset: Think about identity management (Entra ID, RBAC), secrets management (Key Vault), network security (NSGs, private endpoints), encryption, and compliance (Azure Policy, Defender for Cloud) in every design.

Scalability and Cost Awareness: Design for high availability and auto-scaling using Azure services. Discuss Reserved Instances, Spot VMs, storage tiering, and how you would optimise costs using Azure Cost Management.

DevOps Competency: Demonstrate understanding of Infrastructure as Code (Bicep, ARM templates, Terraform), Azure DevOps Pipelines, containerisation (AKS, Azure Container Registry), and CI/CD practices.

Communication: Explain your thinking clearly without jargon overload. Interviewers want to understand your reasoning, not be impressed by acronyms. Ask for feedback and iterate on your solutions.

Frequently Asked Questions

What is the difference between an Azure Engineer and a Cloud Engineer?

An Azure Engineer specialises exclusively in Microsoft Azure services (VNets, App Service, AKS, Azure DevOps, Entra ID, etc.) and has deep hands-on expertise in configuring and managing these services. A Cloud Engineer works across multiple cloud platforms (AWS, GCP, Azure) with a more cloud-agnostic approach. Azure Engineers go deeper into Azure-specific services and tools, whilst Cloud Engineers understand broader cloud concepts applicable across platforms. If you're interviewing specifically for Azure, you need Azure Engineer expertise.

How does an Azure Engineer differ from an Azure Solutions Architect?

An Azure Engineer is hands-on and implementation-focused—they deploy, configure, and manage Azure resources using Azure VNets, App Service, AKS, Azure DevOps, and other services. An Azure Solutions Architect designs comprehensive cloud solutions at a strategic level, considering business requirements, scalability, cost, and alignment with Azure best practices. Architects spend more time designing; Engineers spend more time building and troubleshooting. See our Azure Solutions Architect interview guide for architecture-level questions.

What Azure services should I know for an Azure Engineer interview?

Master these core services: Azure Virtual Networks (VNets), Network Security Groups (NSGs), Azure Load Balancer, Application Gateway, Azure Front Door, Virtual Machines (VMs), VM Scale Sets (VMSS), Azure App Service, Azure Functions, Blob Storage, Azure Files, Managed Disks, Azure Entra ID (formerly Azure AD), RBAC, Managed Identities, Key Vault, Azure Policy, Defender for Cloud, Azure Monitor, Log Analytics, Application Insights, AKS, Azure Container Registry (ACR), ARM templates, Bicep, Terraform, Azure DevOps Pipelines, Azure Cost Management + Billing, and Cosmos DB. Focus on understanding when to use each service.

How should I prepare for the technical portions of an Azure Engineer interview?

Build hands-on projects on Azure: deploy a multi-tier application using VNets and NSGs, set up an App Service with auto-scaling and monitoring, containerise an application and deploy it to AKS, configure CI/CD pipelines with Azure DevOps, and manage secrets with Key Vault. Study Azure documentation and Microsoft Learn modules. Practise explaining your architectural decisions, trade-offs, and cost considerations. Use Azure free credits to experiment without financial risk. Work through real-world scenarios on your projects.

What is Infrastructure as Code (IaC) and why is it important for Azure Engineers?

Infrastructure as Code means defining Azure infrastructure (VNets, VMs, databases, etc.) in code—using ARM templates, Bicep, or Terraform—rather than clicking the Azure portal. IaC enables version control, repeatability, automation, and easy scaling. Azure Engineers must be comfortable writing and maintaining infrastructure code. Bicep is Microsoft's recommended alternative to ARM templates. Terraform is popular for multi-cloud environments. Version control your IaC with Git, automate deployments with Azure DevOps Pipelines, and practise deploying entire environments from code.

How do I explain a production outage or failure in my Azure Engineer interview?

Use the STAR method: Situation (what happened), Task (your role), Action (what you did to investigate and fix), Result (outcome and lessons learned). Focus on your troubleshooting methodology: checking Azure Monitor and Log Analytics for errors, reviewing NSG rules or Application Gateway configuration, examining application logs, and testing in a non-production environment first. Explain what you learned and how you prevented recurrence. Interviewers want to see systematic problem-solving and ownership, not blame-shifting.

How do I demonstrate cost awareness in an Azure Engineer interview?

When designing architectures, mention Azure Cost Management + Billing analysis tools. Discuss right-sizing resources, using Reserved Instances (RIs) for predictable workloads, Spot VMs for non-critical workloads, and storage tiering (Hot/Cool/Archive in Blob Storage). Explain how you would set up chargeback models using tags and subscriptions. Show awareness of egress costs and how to minimise data transfer. Mention shutdown policies for non-production resources. Demonstrate that you think about both performance and cost when making architectural decisions.

What should I know about Azure Entra ID and RBAC for my interview?

Azure Entra ID (formerly Azure AD) is Microsoft's identity and access management service. Understand authentication (verifying who you are) vs authorisation (what you can do). RBAC (Role-Based Access Control) assigns roles (Owner, Contributor, Reader, custom roles) to principals (users, groups, service principals) at scopes (subscription, resource group, resource). Managed Identities allow Azure resources to authenticate without storing credentials. Explain how you would design a multi-tenant identity strategy, create custom roles for least privilege, and audit access using Azure Monitor logs. Understand the difference between service principals and managed identities.
